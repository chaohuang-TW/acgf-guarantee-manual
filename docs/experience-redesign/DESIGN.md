# Experience Redesign 1.0 — 編輯式閱讀工作台

基準：`212a9e79a2779296c45e6f6907c90e7d8dc0d4f2`。分支：`codex/manual-experience-redesign`。
本輪只產生本機設計驗收候選版，不是基金官方網站、不宣稱得獎、不部署。

## 設計決策與三個方向

以真實首頁與「保證貸款到期未獲清償之處理」內容做三組桌機1440與手機390試稿，共12張。

| 方向 | 資訊分配與排字 | 判斷 |
| --- | --- | --- |
| A 編輯式閱讀工作台 | 首頁查詢與身份並列；正文主柱＋主題側欄；按需來源核對 | 採用架構，另外收斂手機前導資訊 |
| B 任務目錄 | 查詢全寬、業務入口雙欄密集表列；閱讀左欄較寬 | 手機查詢直接，但正文空間不足、工具感過強 |
| C 專注出版 | 置中大標、單一寬閱讀柱、章節橫列 | 個性清楚，但手機前導過長，來源核對不夠直接 |

A不是舊版深藍卡片換色。新版用限寬中文、正式編號、分隔線與留白建立秩序；不用照片、AI圖、背景影片、外部字型、圖示套件或新框架。
相關作品與可用／不可用機制見[官方研究](RESEARCH.md)。獲獎與適用性分開判斷。

## 三層資訊架構

1. 全站：全文搜尋 → 完整目錄 → 書表 → 附錄與查索表 → 版本與來源。PDF是明確新分頁動作。
2. 主題：同篇章節／當前章節、上一節與下一節。手機原生收合；目前項目有`aria-current`。
3. 本頁：條款目錄、搜尋命中、已確認相關書表、來源核對、正文字級。

任務路徑：查詢 → 讀原文脈絡 → 確認相關書表 → 原頁/PDF核對 → 返回原查詢。
首頁「熱門關鍵字」改成無人氣宣稱的「查詢範例」。集中式搜尋仍只有首頁與完整目錄兩處；不新增內容頁搜尋欄。

## 閱讀工作區

正文與來源始終不同角色。工具按既有正常來源連結／page hook找到實體頁，僅在開啟或選頁時fetch該頁。
桌面可並列；手機原生modal。開關前後以當前可見原文段落補償布局位移，不改URL、不複製正文到搜尋模型。
已有原頁影像按完整比例顯示，未準備原頁影像的頁面明確提示改開原始PDF；既有文字層收合供核對。
預覽錯誤提示保留原始PDF入口。沒有獨立書表檔案就不偽裝單張PDF/Word下載。

## 搜尋呈現與效能邊界

相關度、概念、意圖、格式canonicalization、去重與零結果建議保持正式基準。
唯一搜尋核心仍是`assets/js/search.js`的既有純函式。原生Worker只import這份核心，排程原函式與摘要/命中位置計算；不另寫算法、不改索引、不用API或外部服務。
不支援Worker時走同一同步函式。UI用request版本避免舊查詢／建議覆蓋新輸入，IME組字期間不提早Enter搜尋。
結果用正常文字列表、安全DOM與漸進篩選；無分數展示。Query/type/fromSearch、Back/Forward、分享連結與頁內命中契約保留。
